## Skipped Issues

### CR-03: Storefront visitor identity is an unsigned client-generated localStorage UUID

**File:** `lib/chat-ui/adapters/storefront.ts:13-19`, `extensions-src/chat-drawer/entry.tsx:28-39`
**Reason:** Skipped — requires an architectural change, not a patch. The correct fix (server-minted HMAC-signed visitor id delivered as a cookie on the shop domain via App Proxy, verified in `withAppProxyHmac`-wrapped routes) spans: a new signing/verification module, cookie minting on a first-touch App Proxy response, signature enforcement across 5 proxy route groups (`chat`, `conversations`, `conversations/[id]`, `saved-products`, `saved-products/[productId]`), client transport changes (`storefront.ts`, `entry.tsx`, `db-backed.ts` stores), and rewrites of ~7 test files that currently send plain UUIDs. A half-applied version would break the working chat flow without delivering the security property. Recommend a dedicated plan/phase (it is the locked "signed cookie" constraint from PROJECT.md, so it must land before drawer launch).
**Original issue:** Visitor identity is `crypto.randomUUID()` persisted in localStorage and sent unsigned in the request body; the per-visitor rate limit keys on this client-controlled value, identity is rotatable/forgeable, and `mergeVisitorIntoCustomer` accepts any claimed visitor id.

### WR-08: `shopify.app.toml` committed with ngrok dev-tunnel URLs

**File:** `shopify.app.toml:5,18-24`
**Reason:** Skipped — requires a human decision: the stable production `application_url`/`redirect_urls`/`app_proxy.url` values are not discoverable anywhere in the repository (no Vercel domain referenced in config or env examples), and substituting placeholders would break the active dev workflow without making the config deployable. Recommended action for the developer: move the ngrok config to `shopify.app.dev.toml` (used via `shopify app dev --config dev`) and commit a production config with the real app host before any `shopify app deploy` / merge to `main`.
**Original issue:** `application_url`, both `redirect_urls`, and `app_proxy.url` point at an ephemeral (and re-assignable) `*.ngrok-free.app` tunnel; deploying this config breaks OAuth, the embedded app, and the App Proxy.
